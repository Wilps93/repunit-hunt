# Материалы к статье о константе Ленстры — Померанса — Вагстаффа

Воспроизводимый анализ к работе «Схема наблюдения в статистике обобщённых
репьюнитных простых: точный условный критерий константы
Ленстры — Померанса — Вагстаффа». Текущая версия статьи — 3; что изменилось
по сравнению с версией 1, описано в [`CHANGES_v3.md`](CHANGES_v3.md).

Статья существует в двух языковых версиях с одним и тем же содержанием и одними
и теми же числами:

* `paper_ru.tex` — русская, оформлена по ГОСТ Р 7.0.7-2021 (тип статьи, УДК,
  двуязычные подписи, романизированный список источников, сведения об авторе);
* `paper_en.tex` — английская, в международном формате.

Каждое десятичное число обеих версий сверяется с выводом скриптов
(`check_all_numbers_v3.py`), ГОСТ проверяется для русской.

## Быстрый старт

```bash
# 1. Данные (уже лежат в data/, шаг нужен только для обновления)
bash fetch_data.sh          # b-файлы OEIS, основной набор b <= 20
bash fetch_extra.sh         # b = 21..26, проверка границы отбора

# 2. Все числа статьи + рисунки
python3 analysis_v2.py      # [S0]-[S12] -> results_v2.txt, figs_v2/  (около минуты)
bash make_results_v3.sh     # [S13]-[S25] -> results_v3.txt  (около 5 минут;
                            #   --full пересчитывает калибровку c_b, ещё 10 минут)

# 3. Статья
bash build_paper.sh            # -> paper_ru.pdf и paper_en.pdf
bash build_paper.sh paper_en   # только английская
```

## Полная валидация

```bash
bash validate.sh          # прогоны 1-4
bash validate.sh --full   # плюс пересчёт калибровки c_b и последовательностей n < 10^4
```

| Прогон | Что проверяет |
|---|---|
| 1. Чистая комната | всё производное строится заново из `data/` и `paper_*.tex` |
| 2. Сверка | каждое число статьи, ключевые числа, ГОСТ, данные, самоповтор, типографика, PDF |
| 3. Устойчивость к зерну | выводы при трёх зёрнах генератора |
| 4. Живые источники | b-файлы OEIS и фронт GIMPS сегодня (известный дрейф печатается, но не валит прогон) |
| 5. Независимый пересчёт | `repunit-hunt` заново считает все n < 10⁴ (`--full`) |

Код возврата 0 только если пройдено всё. Отдельные проверки:

```bash
python3 check_all_numbers_v3.py   # КАЖДОЕ десятичное число обеих версий против вывода скриптов
python3 check_numbers_v3.py       # ключевые числа обеих версий
python3 check_gost.py             # 32 проверки paper_ru.tex по ГОСТ Р 7.0.7-2021
python3 check_stability_v3.py     # устойчивость к зерну
python3 check_overlap.py          # самоповтор с ранними редакциями
python3 compare_verify.py         # пересчёт n < 10^4 против OEIS
python3 compare_verify_ext.py     # расширенный пересчёт против OEIS
```

Зависимости анализа: `numpy`, `scipy`, `matplotlib`. Сборка статьи:
`texlive-latex-recommended`, `texlive-lang-cyrillic`, `texlive-latex-extra`
(на Windows достаточно TinyTeX с пакетами `babel-russian`, `cyrillic`, `lh`,
`cm-super`, `hyphen-russian`).

## Независимый пересчёт последовательностей

Сверка с OEIS подтверждает, что перечисленные индексы дают простое, но не
гарантирует **полноты** списка. Пропущенный член сдвинул бы `N_b`, а с ним и
обе объединённые оценки. Поэтому все индексы `n < 10^4` пересчитаны подряд
поисковиком из корня репозитория:

```bash
bash ../paper/build_and_verify.sh                 # собрать repunit-hunt
DC=1.0 bash verify_sequences.sh 10000             # сплошной пересчёт
python3 compare_verify.py                         # сверка с OEIS
```

`DC=1.0` включает сплошной double-check: каждый отрицательный вердикт
пересчитывается вторым, независимым бэкендом. Без этого потерянная находка
(ложное «составное» из-за сбоя FFT) остаётся невидимой — именно так был найден
баг в GWNUM-пути, описанный в `FINDINGS.md`, §4.

Текущий результат: **153 члена подтверждены, лишних 0, пропущенных 0**
по всем двадцати основаниям.

Продолжение за n ≥ 10⁴ (диапазонами, с возобновлением) описано в
[`VERIFY_EXTENDED.md`](VERIFY_EXTENDED.md).
